## Dependency notes

- 001 comes before 002 to 010 because it adds `tools/smoke.mjs`, the one-command browser check those plans use as a gate. 012 brings its own check and needs nothing from 001.
- 002, 004, 006 and 009 change the simulation. Each one must bump `SIM_VERSION` in `src/sim/race.js`, re-bake the author ghosts with `node tools/medals.mjs all`, and leave the Worker redeploy to the owner. 008 adds an event and changes no existing one, so it does not bump. 010 and 011 are spikes on branches that do not merge, so they do not bump either. The save key contains the sim version (`src/main.js:37`), so every bump clears local records. The game has not been announced yet, so land these before the launch posts go out.
- 004 and 006 follow 002 because they edit the same functions in `src/sim/race.js` and `src/sim/drive.js`. 006 follows 004 because it uses the `bankDare` function 004 adds to `src/main.js`.
- 005 works with or without 002. Its flip hint is left out when 002 has not landed.
- 007 follows 005 because it reuses `src/hints.js` and the red state label that 005 adds.
- 009 follows 002 because 002 changes how near misses and landings pay, and 009 tunes the amounts on top.
- 011 follows 009 because track changes should be judged with the final gas economy, and it uses 009's `tools/gas-econ.mjs`.
- 010 and 011 are design spikes. They end with a written proposal (`plans/010-slide-proposal.md`, `plans/011-stunt-share-proposal.md`) and a prototype branch, not a merge. Both need the owner: 010 to drive the prototype, 011 to choose among the proposed track changes.
- Several plans add a measuring tool that stays in the repo: `tools/smoke.mjs` (001), `tools/gas-econ.mjs` (009), `tools/slide-lab.mjs` (010), `tools/lap-map.mjs` (011), `tools/first-start.mjs` (012).

## Before any plan: restore the vendored three.js build

The plans were written against commit `9ee19cc`. During planning, commit `f91cac2` landed on `shook` and was pushed. It adds plans 001 to 003, and it also deletes `rl/vendor/three-r169/build/three.module.js`. `index.html:23-24` still loads that file, so the game does not boot from `f91cac2` or anything built on it, and `tests/terrain-lod.test.js` fails with `ERR_MODULE_NOT_FOUND`. `origin/main` is still `9ee19cc`, and the live site still serves the file.

Unless the owner says the deletion was intended, the first executor restores the file on their branch before step 0 of plan 001:

```sh
git checkout 9ee19cc -- rl/vendor/three-r169/build/three.module.js
node --test tests/terrain-lod.test.js   # exit 0
git commit -m "fix(vendor): restore the three.js build that index.html imports"
```

The same commit deleted `assets/audio/build/` (the scripts that build the audio assets). The game does not load those at run time, so the plans do not need them. Whether to keep them is the owner's call.

Baselines quoted in the plans ("157 tests pass at `9ee19cc`") hold once the file is restored. Without it the count is 154 passing tests and one failing file.

`shook` must not be merged to `main` while the file is missing. The merge would take the live game down.

## Evidence the plans rest on

- A scripted cold session and five autopilot runs in headless Chrome on an Apple M4 Pro, 1280x720, taken from `git archive 9ee19cc`.
- Four read-only code audits (driving feel, session flow and HUD, race design and AI, audio and effects). Every cited line was re-read by the advisor.
- Measured facts quoted in the plans:
  - Proving Ground Time Trial, throttle held from GO: 148 mph at 7 s, then a tyre wall. 0 mph for 2 s with no toast before the auto-reset.
  - Proving Ground Grand Prix on autopilot: 4:20.7, airborne 6.4% of samples, boosting 5.5%, longest gap between toasts 44 s.
  - The Lineup on autopilot: clears at 11.2, 47.9, 84.2 and 121.2 s.
  - Enter to GO on the first race of a session: 10.2 s for a 2 s countdown with one 6.2 s frame on a cold shader cache, and 2.9 to 4.2 s with a 0.3 to 1.2 s frame on a warm one. Restart to GO: 2.0 s. The cause is in plan 012.
  - Where a clean lap goes (rival AI at full pace): 30% to 38% braking on three of the four circuits, and 2% to 16% on a wall or in the air. The table is in plan 011.
  - Gas earned per lap by the rival AI: 0.21 to 1.19 tanks, which is 2% to 6% of the lap spent boosting. The table is in plan 009.
  - A held steering key settles the car 5 degrees off its path at every speed. Opening the steering lock 2.5 times gives a steady 16 to 19 degree slide that never spins. The tables are in plan 010.
  - Frame times once racing, Launch Complex at night: p50 16.7 ms, p99 16.8 ms.

## Findings without a plan

- A second and third camera (far chase, bumper, look-back). `src/input.js:1-12` has no camera action. Worth doing after 003 settles the default camera.
- Golden-hour haze hides the far road (`src/render/post.js:284-292`, `:407`). Trackside braking boards already exist (`src/render/circuit.js`) but are 1.7 m wide. 005 adds a BRAKE cue to the HUD, which covers the worst case. The fog itself is an art-direction call.
- Touch controls on circuits: binary throttle, no reset button, and a resting thumb can hop (`src/touch.js:10`, `:64`). Needs a real phone before it is specified.
- A three-venue cup. Results print "Winner · 25 points" (`src/main.js:485`, `:554`) and nothing stores them. Wait for 008, since a cup of four-minute races is the wrong shape.
- A daily streak and stored daily rank (`src/main.js:272`, `:519`), and a daily modifier (`src/sim/daily.js`).
- Sparks, tyre smoke and landing dust on tarmac. No plan covers them: they need art direction with a visual review. Car damage is not planned.
- The respawn speed cap reads the wreck site, not the restart site (`src/sim/race.js:138`). It may be an intended penalty. Plan 012's maintenance notes carry the question for the owner.

## Findings considered and rejected

- Hit-pause or slow motion on impacts: `docs/feel.md` decides against it because the sim is fixed at 120 Hz and a pause freezes the whole field.
- Rubber-banding for rivals: decided against in the design. Plan 002 adds a slower fixed tier instead.
- Passive gas refill: decided against. Plan 009 raises earned income instead.
- "Rivals spread out and the race becomes a time trial": not true. The nearest rival was within 25 m for 45% of a Proving race and 95% of a Launch race.
- "The frame rate is poor": not true once racing. The first-start freeze is real and plan 012 fixes it.
- "The Trench author run stalls in the first roll": not true. The advisor saw it in a trace that fed the autopilot's inputs to the sim unrounded. The game and `tools/medals.mjs` round inputs to the recorded format, and with rounding the run takes 22.208 s with no stall at every autopilot skill tried. A less cautious autopilot gains under 1 s.
- "The camera clips through trench walls": a guess from code. Captured trench frames show no clipping.
- Canyon pass-by sounds may click (`src/audio.js` `passBy`): unverified by ear, low value.
